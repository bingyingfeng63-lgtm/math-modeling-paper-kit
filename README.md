# 数模论文写作工具包（math-modeling-paper-kit）

一套可跨届复用的「数学建模论文写作」规范与工作流模板。把「赛题—代码—结果」翻译成「能写什么、不能写什么、怎么规范排版」，并给出提交前验收清单。

## 一、项目简介与用途

本仓库是**纯文档仓库**：只有写作规范、赛事规则层、验收清单和三份工作流模板，没有代码、没有构建步骤。用途是把数模论文写作中被反复踩坑的环节固化成「通用层 + 赛事层」的可复用规范，每届比赛直接 clone 套用。

**为什么做这个**

数模论文的痛点不是「不会建模」，而是：写完才发现公式没交叉引用、图表编号乱、结果和代码对不上、AI 声明缺失、占位符残留。本仓库把这些经验固化成可复用的规范 + 模板，每届比赛直接 clone 套用。

**它做什么**

- 明确「赛题要求 — 数据与代码 — 模型公式 — 结果产物 — 正文结论 — 提交文件」的最小闭环（见 `01`）。
- 用通用层（`01`）+ 赛事层（`02`）分离结构，换比赛只替换赛事层。
- 提供三份可复制的写作工作流模板（`04`），把代码与结果翻译成可写的论文段落。
- 提供提交前逐项勾选的最小验收清单（`03`）。

**它不做什么**

- 不含任何具体赛题、论文正文、建模代码与数据。
- 不收录、不转发任何官方 docx / pdf 原文件（版权与版本过期问题），官方文件获取方式见 `05`。
- 不是建模教程，也不提供算法实现或求解器；它只管「写作、核验、提交」这一段。
- 不替代人工终审：`01` 的复盘方法完成的是写作规范与产物审计闭环，不等同于模型结论、参考文献真实性或最终提交资格已经通过人工终审。

## 二、环境依赖与安装步骤

**依赖说明**：本仓库没有任何代码，因此**没有依赖、没有构建步骤、没有包管理器**，不需要 `npm install` / `pip install` 之类操作。

**写作时你会用到的工具**（依据 `01-通用写作规范/通用数模论文写作规范.md` 第二节「写作使用工具」，均为通用软件，本仓库不提供）：

| 工具 | 用途 |
|---|---|
| Word 或 WPS | 正式排版工具；使用原生样式、OMML 公式、题注、书签、`SEQ/REF/PAGE` 域 |
| Python | 数据清洗、建模、求解、复算、制图和一致性检查（选题需要时才用；本仓库不含任何代码） |
| Excel | 查看和核对结果表 |
| Markdown 编辑器 | 草稿、证据清单和修改说明；不代替官方 Word 模板 |
| PDF 阅读器 | 最终逐页回读；Word 能打开不等于排版已通过 |

按 `01` 的建议：不为单次排版新增复杂工具链，Word、Python、Excel、PDF 四件套通常已足够。

**获取仓库**：

```bash
git clone https://github.com/bingyingfeng63-lgtm/math-modeling-paper-kit.git
cd math-modeling-paper-kit
```

本仓库的公开主页是 GitHub 上的 [`bingyingfeng63-lgtm/math-modeling-paper-kit`](https://github.com/bingyingfeng63-lgtm/math-modeling-paper-kit)；原始上游是项目小组的 Gitea 仓库 `git.uozi.com/annafby/math-modeling-paper-kit`（私有，clone 需要访问令牌）。日常获取与协作请使用上面的 GitHub 地址。

仓库已通过 `.gitignore` 忽略 `.DS_Store`、`__pycache__/`、`*.pyc`、`.venv/`、`*.docx`、`*.pdf`、`*.xlsx`、`*.png`，因此本地生成的论文与图表产物不会被 Git 跟踪。

## 三、快速开始 / 使用示例

下面是把本仓库用于当届比赛的推荐流程，可照做。

### 第 0 步：先拿官方文件

到赛事官网下载**当届**官方论文模板、格式规范与提交说明、AI 使用章程等（渠道见 `05-官方模板获取指引.md`）。这一步必须最先做，因为官方文件优先级最高。

### 第 1 步：获取仓库

```bash
git clone https://github.com/bingyingfeng63-lgtm/math-modeling-paper-kit.git
```

也可以直接把本仓库复制到一个新目录使用；若用 clone，可在此基础上另开分支，把当届内容与规范本体分开。

### 第 2 步：建当届项目目录，并复制三份模板

在仓库根目录下建一个当届项目目录（示例用 `2026-华数杯`），把 `04` 的三份模板复制过去并去掉文件名里的「`_模板`」后缀。

Windows PowerShell：

```powershell
New-Item -ItemType Directory -Force 2026-华数杯 | Out-Null
Copy-Item "04-写作工作流模板\论文写作提取与核验报告_模板.md" "2026-华数杯\论文写作提取与核验报告.md"
Copy-Item "04-写作工作流模板\证据与待确认清单_模板.md" "2026-华数杯\证据与待确认清单.md"
Copy-Item "04-写作工作流模板\论文阅读指南_模板.md" "2026-华数杯\论文阅读指南.md"
```

macOS / Linux：

```bash
mkdir -p 2026-华数杯
cp "04-写作工作流模板/论文写作提取与核验报告_模板.md" "2026-华数杯/论文写作提取与核验报告.md"
cp "04-写作工作流模板/证据与待确认清单_模板.md" "2026-华数杯/证据与待确认清单.md"
cp "04-写作工作流模板/论文阅读指南_模板.md" "2026-华数杯/论文阅读指南.md"
```

### 第 3 步：对规则

打开当届官方《论文格式规范与提交说明》，与 `02-华数杯规则层/华数杯格式规则.md` 逐条对照，把赛事特定数值（页数、文件大小、查重率等）更新为当届口径；有出入时以官方文件为准，并回改规则层。

### 第 4 步：写核验报告，钉证据

1. 填 `2026-华数杯/论文写作提取与核验报告.md`：按「结论先行 → 题目拆解 → 材料作用 → 可直接写的内容 → 各模块能写什么/不能写什么 → 图表建议 → 章节结构 → 返工清单 → 证据索引 → 最终写作判断」逐节填写，把「代码 / 结果 / 数据」翻译成「论文能写什么」。
2. 填 `2026-华数杯/证据与待确认清单.md`：一条主张一行证据，逐个编号（`E01`、`E02`…），并登记关键文件指纹与主张核验结果。

### 第 5 步：写正文

按 `01-通用写作规范/通用数模论文写作规范.md` 的公式、图表、排版、引用、语言要求落笔，用 `2026-华数杯/论文阅读指南.md` 定位每段对应的代码位置，最终写入官方 Word 模板（Markdown 只用于草稿与清单）。

### 第 6 步：提交前验收

过一遍 `03-验收清单/提交前最小验收清单.md`，执行「全选—更新域」，导出 PDF 后逐页检查字体、公式、表格、图片、页码和分页，再核对支撑材料。

## 五、常见问题 / 注意事项（FAQ）

**1. 官方论文模板、格式规范、AI 章程从哪里来？**
从赛事官网自取，路径见 `05-官方模板获取指引.md`：华数杯在官网「下载中心 / 竞赛须知」栏目（论文模板 docx、格式规范与提交说明 pdf、人工智能工具使用章程 pdf、参赛承诺书 docx）；国赛在官网「下载」栏目（论文标准模板 / 论文格式规范、承诺书 / 支撑材料说明）。本仓库不收录、不转发官方原文件。

**2. 为什么仓库里没有赛题、论文正文、建模代码和数据？**
本仓库只含「方法论 + 空模板」，定位是跨届复用的规范本体，因此不包含任何具体赛题、论文正文、官方原文件和代码数据。

**3. 模板里的占位符怎么填？**
`04` 三份模板中的占位符（如 `…`、`（示例）`、`E01`、`C01`、`D01`）需按当届项目实际逐条填写；凡引用具体数值，必须回指证据编号。提交前全文搜索 `xxxx`、`TODO`、示例句、错误引用等残留，确认清空（见 `03`）。

**4. 换一个比赛，需要改哪些文件？**
只需替换赛事层：更新 `02`（或新增一个同级赛事目录）与 `05` 中的对应渠道。`01` 是通用层，不含页数、字号、查重率等赛事数值，通常无需改动。注意 `02` 中「华数杯」的数值仅为参考，换赛事时必须以当届官方《论文格式规范与提交说明》为准。

**5. `02` 里写的页数、大小、查重率能直接用吗？**
不能直接当依据。`02` 明确说明它是「记忆外挂，不作为官方依据」，其中数字（20 页、20 MB、30%/40%、40% 等）会随届次变化。华数杯口径现为：正文尽量控制在 20 页以内；论文提交为单一 PDF 或 Word（建议 PDF）且不超过 20 MB；支撑材料压缩为 ZIP 或 RAR 不超过 20 MB；期刊库查重率不超过 30%，同题自建库不超过 40%；AIGC 检测率须低于 40%——**一律以当届官方文件为准**，并与官方文件对照后回改规则层。

**6. 查重与 AI 声明要注意什么？**
按组委会《人工智能工具使用章程》执行：在参考文献之前设置「AI 工具使用声明」写明实际用途；在参考文献中列出 AI 工具的名称、版本/型号、开发机构/公司、使用日期；附录提供工具与版本、使用环节、关键 Prompt 与回复摘要、采纳内容及人工修改情况；用 AI 辅助编程时，程序开头按章程写明工具名称、版本/型号、开发机构和版本发布日期；AI 辅助制作的图表必须标识来源与人工修改情况。不得让 AI 代替核心建模创新、伪造数据、生成作者信息或直接生成整篇论文，所有 AI 输出必须由参赛队理解、复核并改写。具体查重率与 AIGC 检测阈值以赛事规则层/当届官方文件为准。

**7. 提交形式和匿名要求是什么？**
第一页填写参赛组别、队号、论文题目、摘要和关键词，摘要不得超过第一页（不写英文摘要和英文关键词）；正文从第二页开始，不设置目录；正文和附录不得有页眉，不得出现姓名、学校等身份信息；参考文献和附录置于正文之后。论文与支撑材料均需匿名、命名正确、大小合规，并保留可复现代码和必要输出（见 `02`、`03`）。

**8. 正文能不能直接用 Markdown 交？**
不能。Markdown 只用于草稿、证据清单和修改说明，正式排版须使用官方 Word 模板（公式用 Word 原生 OMML，图表用原生三线表与自动编号、`REF` 域交叉引用），最终导出 PDF 后逐页回读。

**9. 为什么 `*.docx`、`*.pdf`、`*.xlsx`、`*.png` 被 `.gitignore` 忽略？**
因为这是文档仓库，本地生成的论文与图表产物不纳入版本跟踪；规范正文与模板才是需要版本管理的内容。

**10. 核验报告、证据清单和阅读指南谁先写？**
在写作前/中并行推进：先用「核验报告」定写作边界（能写什么、不能写什么），用「证据清单」把每条主张钉到证据上（一条主张一行），再用「阅读指南」把代码位置映射到具体论文章节，最后按 `01` 规范落笔。

## 七、注意事项：切勿提交凭据

本仓库是**公开仓库**，任何被提交的内容都会永久留在 Git 历史中并可被公开检索——即使事后删掉文件，旧提交里依然存在。请遵守：

- **不要提交真实凭据**：API key、访问令牌、密码、私钥、`.env`、`auth.json`、数据库连接串等一律不要入库。
- **密钥字段留空或写成占位符**（如 `YOUR_API_KEY_HERE`），改由环境变量或运行时的本地配置文件注入。
- **提交前自查**：用 `git diff --cached` 逐项复核改动，并可用 `git grep -nE "(api[_-]?key|secret|token|password)"` 做一次粗筛。
- **一旦误提交**：立刻到对应平台**作废并重新签发**该凭据——改写历史无法撤回已经发生的公开暴露，之后再决定是否清理历史。

同理，本仓库不收录官方原文件、赛题与个人数据（见上文「六、约定」）；提交当届内容前请确认不含他人隐私信息。
